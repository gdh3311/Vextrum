# 교체 추천 엔진 (Phase 2)

코드: `backend/app/workbench.py` `replacements`, `validate_replacements`. 화면: 워크스페이스 오른쪽 '교체 추천'.

## 왜 두 단계인가

진단(`VEXTRUM_V4_DIAGNOSTIC_REPORT.md` 4장)에서 정적 초안 점수와 실제 모의전 승률 변화의 순위 상관은 0.067이었다.
그래서 정적 점수는 **후보를 찾는 데만** 쓰고, "더 낫다"는 결론은 모의전 짝지은 비교로만 낸다. 화면도 둘을 따로 보여 준다.

## 1단계: 정적 후보 (수십 ms)

1. 남은 5마리를 고정하고, 앱의 후보 세트 풀(`auto_team._pool`: 랭커 채용률 기반으로 만든 합법 세트)에서 한 마리씩 넣어 본다.
2. 제외: 같은 종, 같은 도구, 잠긴 자리, 모의전 미구현 요소를 가진 세트.
3. 팀 프로필(`workbench.profile`): 메타 가중 대응력(최선·차선), 겹친 약점 타입, 물리·특수 편중, 속도 조작 유무.
4. 목적(mode)
   - `best` 최고 성능: 정적 점수 증가
   - `weakness` 약점 보완: 겹친 약점 해소에 가중, 특정 타입 지정 가능(`targetType`)
   - `keep` 전략 유지: 교체 후 전략 가족이 같은 후보만
   - `pivot` 전략 전환: 전략 가족이 바뀌는 후보만
   - `joker` 조커 발굴: 순위 40위 밖
   - `owned` 보유 포켓몬: 사용자가 준 목록만 (API 지원, 화면 입력은 백로그)
5. 후보마다 계산으로 만든 설명: 보완되는 약점 타입, 새로 생기는 약점, 잃는 역할(다른 팀원이 대신하지 않는 것만), 새 역할,
   대응이 8점 이상 바뀌는 메타 포켓몬, 전략 가족 변화, 속도 조작 수 변화, 데이터 출처.

## 2단계: 모의전 검증 (비동기)

1. 원본 + 고른 후보(최대 3)를 **선별 상대군**(시드 41000013)에서 같은 판으로. 마스터볼 CPU, 스타일 5종 순환, 기본 40판.
2. 선별 차이가 큰 상위 2개를 **독립 검증 상대군**(시드 42000029)에서 다시. 기본 80판.
3. 결론: 짝지은 차이의 95% 신뢰구간 하한 > 0 → 개선, 상한 < 0 → 악화, 그 외 → 결론 보류.
4. 선출: 원본과 후보 모두 같은 선출 판단(상대 미리보기 기반)으로 각자 다시 고른다. 선출이 얼마나 바뀌었는지(최다 선봉이 바뀐 상대 유형 비율)를 따로 기록해
   팀 구성 효과와 선출 변화를 구분할 단서를 준다.
5. 미구현 효과가 있으면 `precise: false`.

## 측정

- 정적 후보: 슬롯당 12~16ms (6자리)
- 검증 예시(하이퍼볼, 선별 20판 + 검증 40판, 후보 2): API 왕복 포함 수 초. 마스터볼 기본값은 판 수에 비례해 더 걸린다.

## 테스트 (`backend/tests/test_workbench.py`)

- 후보는 같은 종·같은 도구를 넣지 않고 규칙을 지킨다 · 조커 모드는 40위 밖 · 보유 모드는 목록 안
- 잠긴 자리는 거부
- 같은 팀을 후보로 넣으면 선별·검증 차이가 정확히 0 (같은 평가 조건)

## 한계

- 원본 팀의 선출 정책을 최적화하고 비교하는 단계(지시서 3장 1·4번)는 '선출 정책 최적화'의 보류 효과가 없었다는 진단(5.1·7장)에 따라
  선출 판단 재사용으로 대체했다. 정책 최적화 단계는 효과가 확인되면 다시 넣는다.
- "대응 불가능한 위협을 해결하는 세트를 새로 생성"은 후보 풀의 세트 중에서 고르는 방식이다. 새 세트 합성은 백로그.
- 정적 점수의 가중치는 사람이 정한 값이다. 연구 DB의 실제 승패로 보정하는 작업은 백로그.
