# 시뮬레이션 실험실 (Phase 4) · 실전 피드백 (Phase 5)

## 실험실

코드: `workbench.experiment`. 화면: 워크스페이스 오른쪽 '실험실'.

| 실험 유형 | 지원 방식 |
|---|---|
| 현재 팀 vs 대체 팀 | A = 지금 팀, B = 저장된 다른 팀 (팀 복제 후 한 곳 수정) |
| 현재 세트 vs 다른 세트 | 같은 방식 (복제 팀에서 세트만 수정) |
| 선봉 A vs 선봉 B | API `leadA` / `leadB` (상대와 무관하게 이 4마리·순서로 선출, `apply_policy`의 `*` 열쇠). 화면 입력은 백로그 |
| 상대 특정 포켓몬·아키타입 중심 | API `archetypes` (상대 플레이북 7종 중 선택) |
| CPU 난이도별 | 하이퍼볼·마스터볼·챔피언 (API는 몬스터볼·슈퍼볼 포함) |
| CPU 스타일별 | API `styles` (기본 5종 순환), 결과에 스타일별 승점 |
| 날씨·순풍·트릭룸 실행 | 결과의 '실제로 전개한 전술' 횟수 |

결과: 승률·95% 범위, 판 수, CPU 난이도·스타일, 상대 유형별, 패배 태그·원인, 포켓몬별 선출률·킬·승률, 선출별 결과, 실제 전개한 전술,
A·B 짝지은 차이(개선/악화/결론 보류), 정밀 여부, 버전(시뮬레이터·규칙·데이터).

원칙
- A·B는 같은 시드(43000019)의 같은 상대·같은 난수.
- 교체 추천(Phase 2)은 선별과 독립 검증 상대군을 나눈다. 사용자가 직접 돌리는 실험은 한 상대군에서의 비교이며, 같은 실험을 반복해도 같은 결과가 나온다.
- 규칙 위반 팀은 실험하지 않는다. 미구현 효과가 있으면 '정밀하지 않음'.
- 팀을 고치면 결과에 '이전 버전' 경고.

## 실전 피드백

코드: `workbench.feedback`. 기록 입력은 기존 상대 분석 화면의 전적 기록(`match_journal`, 기기 저장)을 쓴다.
기록 항목: 시각, 형식, 팀 이름·세트, 상대 6마리, 내 선출, 상대 선봉·후발, 결과, 메모. (`lossReason` 필드는 분석이 읽지만 입력 화면은 백로그)

분석: 실전 승점률·95% 범위(표본 수 명시), 2판 이상 만나 60% 이상 진 상대, 추천 선출을 따른 판/다르게 고른 판의 결과, 패배 원인 메모 빈도,
다음 실험 가설(대응 실험, 선출 비교).

원칙: 실전 기록은 `source: "real"`로 따로 두고 메타 확률·모의전 결과에 섞지 않는다. 적은 표본은 '경향'으로만 표시.

## 테스트 (`backend/tests/test_workbench.py`)

- 선봉 강제 실험에서 기록된 선봉이 지정한 2마리뿐
- 미구현 도구(선제공격손톱)가 들어가면 `precise: false`
- 실전 기록 3판 분석, `source: real`, 어려운 상대·가설 생성

## 백로그

- 실험 화면에서 선봉·아키타입·스타일 직접 고르기, 여러 실험 결과 나란히 비교, 실험 기록 저장
- 실전 기록 입력에 패배 원인·상대가 쓴 기술·도구·전략 성공 여부 추가, 기록별 모의전 예측(같은 상대 6마리)과 실제 결과 비교
- 배틀 기록 자동 입력: 공식 API·리플레이 공개 여부 미확인. 화면 인식(Battle Data Companion 방식)은 별도 검토
