## 적용 내용과 확인 범위

| 명세 | 반영 및 확인 |
| --- | --- |
| 규칙과 기술 ID | 기존 영문 세트 키와 호환되는 canonical ID를 노출했다. 분함의발구르기는 이전 턴 실패를 추적하며, 땅고르기는 아군을 포함하는 광역 스피드 하락기로 유지한다. 알려진 미구현 기술·특성·도구는 자동 구성과 연구 후보에서 제외한다. 사용자가 지정한 고정 세트는 해당 이름과 함께 오류를 반환한다. 가이드에서 미검증 효과를 표시한다. |
| 메가진화 | 직접 배틀에서 선택한 기술과 함께 메가 슬롯을 전송한다. 기본 폼으로 기다리거나 다른 후보가 나온 뒤 선택할 수 있다. 잘못된 명령은 진화 권리를 소비하지 않는다. 자동 운영의 메가 선택과 교체·진화가 같은 턴에 겹칠 때의 세부 순서는 추가 확인 대상이다. |
| 평가 분리 | 시작 코어 2종의 정렬된 기본 종 키를 해시해 탐색·보류·벤치 감사 풀로 나눈다. 같은 시작 코어의 세트 변형이 여러 풀로 흩어지지 않는다. 나머지 4자리와 세트 재료는 공유한다. 최종 후보 선정 후 마스터볼 상대와 CPU 성향 6개로 보류 성적을 계산하며, 선정 순위에는 사용하지 않는다. 랭커 연습전도 서로의 실제 비공개 세트 대신 공개 종의 대표 세트로 선출한다. |
| 자동연구 | 연구 DB의 탐색 전적과 보류 전적을 분리한다. 일정 세대마다 탐색 상위 팀 한 개의 별도 표본을 저장한다. 같은 팀과 정책은 해당 데이터·규칙·CPU 버전에서 한 번만 기록한다. 팀 자동 구성은 연구 후보를 새로 평가하며 기본 엔진에서는 연구 시드를 최대 4개 사용한다. |
| 전략 설명 | 첫 턴 문장은 실제 선봉, 사용한 기술의 ID, 교체할 후발, 표본과 CPU 정책을 확인한 후 표시한다. `SIM_OBSERVED`는 행동을 관측했다는 상태다. 실패할 수 있는 행동의 성공이나 승리의 인과 효과를 보장하지 않는다. 피해량 추정과 관측 KO 횟수는 각각 표시한다. |

## 예비 비교

비와 트릭룸 요청을 각각 빠른 설정으로 한 번 실행했다. 모든 생성 후보를 동일한 감사 상대·난수로 팀당 27판 재평가했다. 같은 코어를 만난 경기들을 묶어 95% 재표집 범위를 계산했다. 빌드 시간을 측정했으며 동일한 시간 제한을 걸어 비교하는 실험은 별도로 남아 있다. 연구 DB는 빈 임시 복사본을 사용했다. 원자료는 [v4_vs_v5_bench.json](v4_vs_v5_bench.json)에 있다.

| 요청 | v4 평균 · 빌드 | v5 평균 · 빌드 | v6 평균 · 빌드 | v6 − v4 95% 추정 범위 |
| --- | --- | --- | --- | --- |
| 비 | 59.3% · 32.92초 | 59.3% · 34.16초 | 47.5% · 15.93초 | −32.1 ~ +8.0%p |
| 트릭룸 | 29.0% · 38.53초 | 29.0% · 40.54초 | 28.4% · 14.15초 | −8.3 ~ +6.2%p |

이 표본에서 v4와 v5는 두 요청의 게임별 결과가 같았다. v6는 빠르게 끝났으며 두 요청 모두 보류 성능 우위를 확인하기엔 표본이 작다. 기본 엔진은 v6로 유지하고 v5는 비교용으로 둔다. 현재 예비 비교의 숫자는 두 가지 선호 설정과 합성 상대에 해당한다.

## 화면에서 확인할 사례

1. 자동 구성 결과에서 **보류 상대**를 열면 선정 후 평가에 사용한 코어 수, 판 수, 승점률, 전략별 전적을 확인할 수 있다.
2. 자동연구의 누적 전적과 보류 전적을 비교할 수 있다. 아직 보류 평가를 받지 않은 팀에는 표본이 쌓일 때까지 보류 전적이 표시되지 않는다.
3. 직접 배틀에서 메가 후보가 필드에 있을 때 포켓몬 이름 옆 메가진화 버튼을 누르거나 다음 턴까지 기다릴 수 있다.
4. 운영 가이드에서 미구현 효과 목록과 관측된 첫 턴 행동의 조건을 확인할 수 있다.

## 후속 검증

공식 M8 사용률과 실기 기록이 확보되면 실제 관측 팀을 대상으로 새 감사 표본을 만들어야 한다. 이번 평가는 합성 팀의 시작 코어를 분리했다. 실제 팀 계열 전체의 데이터 누출 차단, 매 판의 룰 검증, 검증된 전략 그래프, 턴 정책까지 포함한 공동 최적화, 동일 벽시계 예산에서의 반복 비교는 후속 단계다. 미구현 목록에는 확인된 항목을 넣었으며, 목록에 없는 모든 요소가 완전히 구현되었다는 의미는 아니다.
